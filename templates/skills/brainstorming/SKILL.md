# Brainstorming

Vendored, self-contained. (If `superpowers` is installed, prefer its
`brainstorming` skill.)

## When

Before any creative/build work — a new feature, component, or behavior change.
Process before implementation: this decides *what* and *why* before *how*.

## Process

1. **Understand the request.** Restate it. What problem, for whom, what does
   success look like?
2. **Ask one question at a time.** Prefer concrete choices over open prompts.
   Wait for the answer, reflect it back, then ask the next. Don't batch.
3. **Surface the real forks** — the decisions that change the design. Resolve
   those first; default the rest and say so.
4. **Converge.** Summarize the agreed design and the tradeoffs chosen.
5. **Hand off to planning** (`writing-plans`) once the design is agreed.

## Rules

- Don't jump to a solution before the problem is clear.
- Don't ask what the code or sensible defaults already answer.
- One question per message. Recommend an option when you have a view.
